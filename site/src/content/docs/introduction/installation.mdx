# Installation

Uphill is one binary with no runtime. Release builds cover macOS and Linux on arm64 and x64, and Cargo builds it anywhere Rust runs.

> [!NOTE]
> The npm package is not published yet, so `npx uphill` has nothing to download for now. The install script, the release archives, and Cargo work.

## Install Script

The install script downloads the release archive for the machine, checks its SHA-256 digest against `sha256sums.txt`, and puts the binary in `~/.uphill/bin`. It runs on macOS and on Linux with glibc or musl.

```sh
# Install the latest release to ~/.uphill/bin/uphill.
curl -fsSL https://raw.githubusercontent.com/wevm/uphill/main/install.sh | sh
```

If `~/.uphill/bin` is not on `PATH`, the script prints the line to add to the shell profile. Two environment variables change what it installs:

- **`UPHILL_VERSION`:** The release to install, such as `0.1.0`. The default is the latest release.
- **`UPHILL_INSTALL`:** The install directory. The binary goes to its `bin` directory. The default is `~/.uphill`.

```sh
# Install release 0.1.0 to /opt/uphill/bin/uphill.
curl -fsSL https://raw.githubusercontent.com/wevm/uphill/main/install.sh | UPHILL_VERSION=0.1.0 UPHILL_INSTALL=/opt/uphill sh
```

## npm

The `uphill` package holds the binaries for macOS and Linux on arm64 and x64, and runs the one for the machine. On Linux it runs the static musl build, so one binary serves glibc and musl systems.

```sh
# Run the latest release without installing it.
npx uphill

# Or add it to a project, and run it from a package script.
npm install --save-dev uphill
```

`pnpm dlx uphill` and `bunx uphill` run it the same way. The package declares its operating systems and CPUs, so npm refuses to install it on other platforms.

## Cargo

Cargo builds Uphill from source on any platform that Rust supports. The `--locked` flag builds with the dependency versions in the repository's `Cargo.lock`.

```sh
# Build the main branch and install it to ~/.cargo/bin.
cargo install --locked --git https://github.com/wevm/uphill uphill
```

## Release Archives

Each GitHub Release has one `uphill-<target>.tar.gz` archive per target and a `sha256sums.txt` file. Each archive holds the `uphill` binary.

| Target | Platform |
| --- | --- |
| `aarch64-apple-darwin` | macOS on Apple silicon |
| `x86_64-apple-darwin` | macOS on Intel |
| `aarch64-unknown-linux-gnu` | Linux on arm64 with glibc 2.28 or later |
| `x86_64-unknown-linux-gnu` | Linux on x64 with glibc 2.28 or later |
| `aarch64-unknown-linux-musl` | Linux on arm64, static |
| `x86_64-unknown-linux-musl` | Linux on x64, static |

The musl builds link statically, so they also run on Alpine and on systems with a glibc older than 2.28. The install script selects them on those systems, and the npm package runs them on every Linux system.

```sh
# Download the static x64 build, check its digest, and extract the binary.
curl -fsSLO https://github.com/wevm/uphill/releases/latest/download/uphill-x86_64-unknown-linux-musl.tar.gz
curl -fsSLO https://github.com/wevm/uphill/releases/latest/download/sha256sums.txt
grep ' uphill-x86_64-unknown-linux-musl.tar.gz$' sha256sums.txt | sha256sum -c -
tar -xzf uphill-x86_64-unknown-linux-musl.tar.gz uphill
```

## Check the Install

`uphill --version` prints the installed version.

```sh
# Print the version.
uphill --version
```
